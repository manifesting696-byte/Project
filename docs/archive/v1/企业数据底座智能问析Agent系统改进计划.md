# 企业数据底座智能问析 Agent 系统改进计划

## 1. 改进目标与优先级

本计划依据[代码审计报告](企业数据底座智能问析Agent系统代码审计报告.md)和[系统设计方案](企业数据底座智能问析Agent系统设计方案.md)制定。**首要任务是让模型真正参与规划与分析，并证明下一步行动由上一轮查询结果驱动。** 在这条 Agent 主链路成立后，依次建设①可信语义建模与结构化 IR；②安全、可扩展的 SQL 执行。最后完成生产权限、恢复、观测和验收。

现有系统的固定 SQL、SQLite 副本和 LangGraph 条件分支可作为起点，但不能把规则关键词路由或预写的固定查询顺序算作目标能力。改进遵循 YAGNI：先把供应商交付与来料质量调查做对，不引入通用知识图谱平台、任意代码执行器或没有数据支持的机器学习任务。

**开发边界：** 第一阶段仅在隔离数据快照上调用现有只读、固定参数的查询工具；模型不能提交任意 SQL、修改业务数据或选择身份权限。语义和 SQL 网关完成前，探索结果明确标为演示分析，不作为正式业务指标发布。应用携带数据库管理凭据及自动重建 Schema 的风险需在任何正式部署前消除。

## 2. 阶段路线

| 顺序 | 核心问题 | 主要交付物 | 阶段门槛 |
|---|---|---|---|
| 1 模型驱动、结果驱动的 Agent | 模型是否真正根据证据决定下一步？ | Supervisor、专业节点、运行时增长的任务计划、可检查的执行轨迹 | 改变中间结果会改变后续任务；反证能改变结论或停止 |
| 2 可信语义建模与 IR | 模型提出的业务概念是否有受控定义？ | 离线候选与审核流程、版本化语义对象、绑定 IR、确定性校验 | 未发布定义不能用于正式查询；每个 IR 引用可解析 |
| 3 安全、可扩展的 SQL 执行 | 如何把可信 IR 变成正确且受限的查询？ | 指标编译器、AST 网关、权限与资源限制、结果引用 | 错误 JOIN、危险函数、越权和重复计数被阻断 |
| 4 工程可靠性与正式验收 | 系统能否恢复、追溯并在真实环境运行？ | 最小权限部署、checkpoint 恢复、Langfuse、黄金题库与报告 | 关键数值、过程和安全用例在固定快照上通过 |

各阶段有独立可运行成果。阶段 1 可以先验证 Agent 的真实决策能力，但**不能因其通过就开放任意 SQL 或宣布系统满足正式口径要求**。阶段 2、3 的验收通过后，才允许扩大正式问析范围。

## 3. 阶段 1：建立模型驱动、结果驱动的 Agent 主链路

对应审计问题：P1-2、P1-3，以及 P2-11、P2-14。此阶段是当前最高优先级。

### 3.1 最小实现

1. 接入一个可配置的模型适配层，记录模型名、配置版本、调用耗时、输入输出 token 与结构化输出校验结果。先用一个经过批准的模型完成主链路；无需同时接入多家模型。
2. 在 LangGraph 主图加入 Supervisor 的初始规划节点、执行节点、观察与重规划节点、证据门控和最终校验节点。Supervisor 决定任务级别及下一步，但只能分派受许可工具，不能直接读原始表。
3. 将语义、查询、分析、呈现职责定义成清晰的节点输入输出。第一阶段可合并不需要独立模型上下文的节点，避免为了凑 Agent 数量而重复调用。模型负责提出候选目标、假设和下一步探查；查询、算数、权限与数值核对仍由确定性服务执行。
4. 子任务记录独立 ID、依赖、输入结果引用、触发事实、待区分假设、预期证据、验收条件、预计工具成本、状态与终止条件。初始计划只安排交付筛查。读取结果后，才为实际候选追加质量查询；质量结果再决定材料构成、缺陷原因、交付阶段拆解或停止。
5. 用结构化状态保存候选、事实、反证、证据缺口、计划版本、探索轮次和预算。每次追加写明触发结果引用和决策理由。只有候选集合产生后才考虑按候选并行；并行结果按子任务 ID 合并。
6. 设置硬边界：至多 5 家候选、至多两轮追加探查、有限模型与工具调用、截止时间和重复调用熔断。证据不足时输出部分结论与缺口，不让模型继续猜测原因。

### 3.2 首个验收场景

以设计方案中的问题为主线：2025 年上半年哪些供应商交付恶化，质量是否同步下降，哪些风险最高。必须观察到以下过程，而不只检查最终文案：

- 先查询全部供应商的交付数据，展示两期准时数、发货数和延期情况。
- 根据查询结果生成候选集合；只对候选查询同一发货单队列的质量数据。
- 对供应商 11，交付为 8/10 → 4/10，拒收率约为 2.93% → 1.99%。模型不得直接给出双域恶化结论；应先核查收货覆盖率与材料构成，若无反向证据，再撤回该假设并考虑交付阶段拆解。
- 没有可信候选时，不进入质量分支；质量恶化但材料构成变化时，追加能区分构成效应与类别内变化的探查，或降低结论强度。
- 在隔离数据中改变一项中间结果后，后续任务集合应随之改变。测试断言决策不变量，而非锁死一条节点序列。

### 3.3 阶段交付与通过标准

交付运行轨迹样本、任务状态 Schema、模型输出 Schema、受许可工具清单和过程测试。真实模型调用必须出现在轨迹中；任务追加须能回溯到上一轮结果。固定 SQL 可以暂时作为执行工具，但质量、构成与交付拆解的调用时机必须由观察结果决定。模型给出的任何未经数据支持的根因说法不得进入已核验事实区。

## 4. 阶段 2：可信语义建模与结构化 IR

对应审计问题：P1-1、P1-2，以及 P2-9、P2-10。阶段 1 的 Agent 先证明会规划；本阶段让它只能在可信的业务语义边界内规划。

### 4.1 离线建模与发布

1. 从运行中的数据库读取 Schema、列类型、约束和可访问视图，并对当前快照画像：行数、空值、去重数、日期范围、常见枚举、候选关联覆盖率和联结基数。与 CSV 描述核对，标明哪些是推断、哪些是数据库约束。
2. 使用现有数据说明和脱敏样例让模型提出表、字段、业务对象、关系、维度和指标候选。候选需写明精确字段引用、来源、推断依据和待业务确认的问题；模型无发布权。
3. 程序逐项检查对象格式、字段与类型、关系路径、粒度、指标表达式、时间字段、零分母和授权范围。失败候选留在草稿状态。
4. 先发布最小语义包：发货到货准时率、平均延期天数、来料拒收率，以及必需的供应商、月、季维度和关联关系。采购、质量与数据负责人确认各自负责的口径和关系后，形成不可变版本。
5. 用版本化 YAML 作为编辑源，发布到运行时只读注册表。对象状态至少包含 candidate、reviewed、published、deprecated；依赖变化使受影响的指标待复核。旧任务和旧报告保留所用版本。

### 4.2 在线绑定与 IR

将提问解析成与 SQL 无关的 IR，至少包含指标 ID 与版本、维度、过滤、闭开时间区间、事实粒度、已发布 JOIN 路径、输出要求、授权快照及未解歧义。模型可以提出候选绑定；确定性校验器必须确认每个 ID、版本、路径和粒度均可解析且已发布、已授权。多个口径可能成立时提具体澄清；没有设备、工序等数据时明确拒绝错误映射。

### 4.3 阶段验收

- 未发布、已废弃或无权限的语义对象不能进入正式 IR。
- 随机改动字段或关系版本后，依赖指标能失效并阻止旧定义用于新任务。
- 两项核心指标的 IR 能解释公式、分母、时间、粒度与关系路径；其数值与独立标准 SQL 一致。
- Agent 的下一步探查引用 IR 中的对象 ID，而不是在各节点重新猜测指标公式和 JOIN 路径。

## 5. 阶段 3：安全、可扩展的 SQL 执行

对应审计问题：P1-4、P1-6，以及 P2-10、P2-12、P2-13。以阶段 2 的 IR 为输入，先实现已发布指标的确定性编译，再处理受限临时查询。

### 5.1 查询编译与校验

1. 用受限指标表达式编译参数化 SQL。对多表指标先确定事实粒度与联结基数；跨一对多分支先预聚合，避免重复计数。
2. SQL AST 校验采用允许列表：单条 SELECT、授权视图与逐表列、已发布关系、允许函数、参数占位、合理 LIMIT。解析时正确处理别名与目标数据库方言，不能用各表列名的并集替代逐表授权。
3. 执行前检查计划成本、最大扫描量、超时、并发和行数；执行时使用数据库级只读角色与事务。执行后检查主键去重数、行数膨胀、分子分母、零分母和空结果。
4. 将原始结果存为带权限与版本的引用，向 Agent 返回列、类型、总行数、前 N 行、统计摘要和引用；明细可分页回读。统一错误码区分语法、权限、超时、超量、零结果和数据质量。

### 5.2 阶段验收

- 审计中误通过的危险函数、错误键 JOIN、CROSS JOIN 和极大 LIMIT 被拒绝；合法查询继续运行。
- 写操作、敏感列、跨数据域查询在应用层及数据库层均被拒绝，权限拒绝不触发模型换 SQL 重试。
- 准时率与拒收率在冻结快照上的分子、分母、时间范围及数值与独立 SQL 一致；一对多重复计数用例被阻断或正确预聚合。
- 超时、超量、零行、零分母、NULL 和日期边界均有结构化结果；未完成查询不进入报告事实区。

## 6. 阶段 4：工程可靠性与正式验收

对应审计问题：P1-5、P1-7、P1-8，以及 P2-11 至 P2-15。生产部署风险必须在正式上线前关闭。

1. 将数据导入、Schema 发布和应用启动拆开；禁止应用启动自动执行破坏性 Schema 重建。移除运行容器中的数据库管理凭据，为分析查询和 checkpoint 分配各自最小权限账号。用两个身份验证数据域或明确记录单租户演示边界。
2. 明确 running、waiting_input、partial、completed、failed、blocked 状态转换。用真实中断、同线程恢复、版本核验和幂等键证明 checkpoint 能恢复任务；权限或指标版本变化时使旧分支失效。
3. 接入经批准的 Langfuse 实例，关联任务、模型、计划版本、SQL 预检、查询、分析和报告 observation。传脱敏摘要与哈希，不传供应商联系方式或原始明细；本地业务审计独立保留。
4. 报告输出前核对图表数据、分子分母、时间范围、指标版本、SQL 哈希和结果引用。报告分别写事实、关联、假设、建议与证据缺口。先支持 Markdown 导出；其他格式按实际需要增加。
5. 建立冻结快照、独立黄金 SQL 和版本化题库。覆盖简单、多表、长链路、无候选、反证、构成变化、错误 JOIN、越权、恶意 SQL、超时、空结果、部分分支失败及恢复。评测脚本自动统计通过、失败和未运行项，保留实际命令与退出状态。

**最终验收门槛：** 审计报告的 P1 问题全部关闭；两项核心指标数值和口径正确；写操作与越权用例全部被拒绝；长链路轨迹证明中间结果改变了后续任务；报告中的每个数值可回溯到数据快照、指标版本、SQL 和结果引用。PostgreSQL 或 Langfuse 未实际运行的项目保持“未验证”，不得标为通过。

## 7. 执行与复核约定

每阶段交付变更清单、对应审计问题编号、固定快照与语义版本、真实运行轨迹、测试命令和退出码，以及尚未解决的限制。开发与故障注入使用隔离数据库和测试账号，不直接修改生产业务数据。业务口径发布、数据库 Schema 切换及外部观测服务接入须有可审阅的定义、迁移与回退证据。
