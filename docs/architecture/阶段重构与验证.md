## 数据如何移动

1. HTTP 请求进入 Application.ask，在会话锁内生成 Turn 并写 user_message。
2. Intent 识别本轮操作及引用。归一化分配全局 Request ID，确定依赖顺序，保存 intent_resolved。
3. 准备阶段读取当前版本，将本轮变化合并为完整 spec，同时生成初始 Task DAG。直接回答也保存 Request/spec，但无执行 Task。
4. 同一事务比较版本，再写不可变 Revision、当前 Request、Task 和计划事件。其他独立 Request 不因单项失败一起回滚。
5. 按依赖调度 Task。Request 逻辑输出通过绑定解析到具体 Artifact；工具只读取授权输入，新增 Artifact 保留来源和创建者。
6. 验收逐项检查预期输出，结合真实 Artifact 判断完成、重规划或澄清。模型声称完成不能越过证据校验。
7. 回答将普通文字也写成 Artifact，ResponseBlock 记录产物及所属 Request/Revision。最终 assistant_response 保存卡片顺序，前端读取产物展示。

## 兼容性取舍

- 附件目录示例与“非运行时资产出主包”冲突，本次按后者执行。根目录 ops/ 同时包含在 Docker 镜像和 Python wheel 中。
- 历史 legacy_tasks、legacy_task_revisions 表仍用于旧 Task URL 的兼容查询，属于有效契约。保留真实表名，不通过拆字符串隐藏搜索结果。SQLite 实现和全部离线迁移已移至 ops/migrate/。
- Application、Requests、Supervisor 保留小型兼容接口，具体实现由阶段模块拥有，插件服务名和 checkpoint 内容不变。
- 未把所有底层 ValueError 都改成可重试错误；网络、权限、数据库冲突不会自动当作模型修复处理。
- VersionConflict 拒绝自动重做过时提案；并发测试检查不重试且已有 Revision/Task 不被覆盖。
