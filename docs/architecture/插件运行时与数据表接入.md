# 插件运行时与数据表接入

## 运行结构

采用 Python 实现 DeepSeek Harness 中的服务依赖、作用域注册、可撤销副作用和 Profile/Bundle 组合机制。运行时使用 Python 模块与安装包 entry point 发现插件，应用通过插件提供的服务执行问析。

```text
config/harness.yaml + AGENT_PROFILE + 按顺序应用的补丁
  → Profile 展开 Bundle
  → 发现插件定义并校验配置
  → 检查服务冲突、缺失依赖与依赖环
  → 按依赖顺序初始化插件
  → 注册服务、Agent、工具和事件监听器
  → LangGraph 工作流执行 Request
```

每个数据源由数据库 Provider 负责，数据表作为问析目录条目保存。表接入和移出通过目录管理完成，Agent 和执行循环继续通过统一目录读取可用表。

## 插件契约

```python
from enterprise_agent.plugins import Plugin, PluginConfig

class PolicyConfig(PluginConfig):
    max_tables: int = 4

def apply(ctx, config):
    def check(value):
        if len(value["binding"]["tables"]) > config.max_tables:
            raise ValueError("查询使用的数据表数量超过插件配置")

    ctx.on("sql/before_execute", check, priority=10)

PLUGIN = Plugin(
    plugin_id="query.policy",
    version="1.0.0",
    apply=apply,
    config_schema=PolicyConfig,
)
```

Plugin 的 requires 声明消费的服务名，provides 声明提供的服务名。运行时据此解析依赖，配置列表的书写顺序可以独立于初始化顺序。version 记录插件实现版本。

| Context 方法 | 作用 |
| --- | --- |
| require(name) | 获取已声明依赖的服务 |
| provide(name, instance) | 注册插件声明提供的服务 |
| on(event, handler, priority=0) | 订阅运行时事件，数字较小的处理器先执行 |
| tool(role, group, factory) | 为角色注册一个工具组，factory(context, toolbox) 返回工具字典 |
| agent(name, implementation, description) | 注册专业 Agent 和模型可见的职责说明，需要声明 specialists 依赖 |
| defer(cleanup) | 登记资源关闭或其他撤销动作 |

apply 完成初始化，可以返回一个额外清理函数。卸载按依赖逆序释放插件，每个作用域内的副作用按登记逆序撤销。订阅、服务、工具组和 Agent 注册均绑定其所属作用域。插件创建的文件句柄、连接池或后台资源应在获取后立即用 defer 登记关闭函数。

Application 构造参数注入的模型、存储或 Agent 按借入对象使用，其生命周期由调用方管理。

## 发现与加载

支持三种来源。

- 内置插件 ID，例如 agent.presentation。
- Python 导出路径，例如 my_package.policy:PLUGIN。
- 安装包的 enterprise_agent.plugins entry point。

扩展包可以声明如下入口。

```toml
[project.entry-points."enterprise_agent.plugins"]
query_policy = "my_package.policy:PLUGIN"
```

安装后可通过 query_policy 发现并加载。插件运行于应用 Python 进程，使用该进程的权限，管理接口仅向管理员开放。

动态加载时依赖服务需要已经启用。Profile 启动会统一解析全部配置行的依赖后排序。reload 根据已导入的插件定义和配置重建实例，并重建依赖方。插件代码版本随安装包更新和应用部署管理。

## Profile 与 Bundle

默认配置位于 config/harness.yaml。

| Profile | 加载能力 |
| --- | --- |
| default | 标准问析、图表报告、摘要和日志观测 |
| data | 标准数据问析、摘要和日志观测 |
| minimal | Supervisor、目录、工具基础与工作流 |

环境变量 AGENT_PROFILE 选择 Profile，AGENT_PLUGIN_CONFIG 指定配置文件。AGENT_PLUGIN_PATCHES 按操作系统路径分隔符连接补丁文件，Windows 使用分号。

Profile 依次展开 bundles，再应用自己的 plugins 行，最后依次应用外部补丁。同一 id 的后续行替换前一行的完整 config。省略 plugin 时沿用前一行的来源，enabled 为 false 时禁用该实例。循环 Bundle、重复实例、服务冲突和缺失依赖会在插件初始化前报错。

例如，下面的补丁禁用展示 Agent，并指定 PostgreSQL 数据源 Schema 和稳定标识。

```yaml
plugins:
  - id: agent.presentation
    enabled: false
  - id: database.readonly
    config:
      schema: analysis
      source_id: supply-chain-analysis
```

数据库 Provider 使用 DATABASE_URL 连接 PostgreSQL，默认读取 analysis Schema 中当前账号可查询的表和视图。插件可设置 dsn、schema、source_id。凭据通过环境变量传入。默认 Profile 为数据源配置稳定 source_id，使本机与 Docker 的连接地址变化时仍使用同一份目录。不同逻辑数据源应使用不同 source_id。未配置时根据连接身份和 Schema 计算标识。

## 动态切换与生命周期

ask、Request 恢复和 Turn 恢复会持有运行许可。运行期间，插件切换和目录变更返回明确错误，调用方可以在执行结束后重试。多个会话可以同时持有运行许可。

切换时先校验完整配置，再按逆依赖顺序释放受影响插件，随后依次初始化新实例。未变化的独立插件保持当前实例。初始化失败会释放新作用域并重新初始化原配置。原配置恢复失败时，运行时进入异常状态，后续执行返回错误，关闭时仍尝试清理全部已登记资源。

HTTP 应用退出会关闭缓存的 Application。直接创建 Application 的调用方可使用 with Application(...) 或显式 close()。

| 管理接口 | 功能 |
| --- | --- |
| GET /runtime/plugins | 查看已加载插件、依赖、服务、监听器和已发现入口 |
| POST /runtime/plugins/load | 根据 id、plugin、config 加载插件 |
| POST /runtime/plugins/{id}/unload | 卸载插件，cascade=true 时连同依赖方释放 |
| POST /runtime/plugins/{id}/reload | 重建插件与依赖方，config 可替换当前配置 |
| POST /runtime/profile/reload | 重新读取配置文件并选择 profile |

运行时装卸调整当前进程的能力组合，启动组合由配置文件管理。GET 管理响应返回插件身份和依赖信息，配置值保留在插件作用域内。

## 事件与会话账本

session_events 保存对话、意图、计划、工具调用和正式回复，用于历史回读与执行恢复。运行时事件分发给当前已订阅的处理器，订阅随插件卸载释放。

| 事件 | 语义 |
| --- | --- |
| plugin/loaded、plugin/unloaded | 生命周期观测 |
| tool/before_execute | 已授权工具执行前检查，可抛异常阻止执行 |
| tool/after_execute | 工具返回后处理，可抛异常使本次工具调用报错 |
| tool/error | 工具失败观测 |
| sql/before_execute | SQL 经原有只读与范围校验后，执行前的策略检查 |
| sql/after_execute | SQL 完成后的行数与字段观测 |
| agent/before_execute、agent/after_execute | 专业 Agent 执行前检查和执行后观测 |
| response/published | 正式回复保存后的观测，摘要插件订阅此事件 |
| session/event | Supervisor 和专业 Task 的 emit 回调保存事件后发出的通知 |
| catalog/before_change、catalog/changed | 目录变更前检查和变更后观测 |

emit 执行检查类处理器并传播异常，notify 逐个调用观测处理器并记录异常。工具执行使用授权工具表和原始参数，检查处理器读取其副本。

## 数据表接入与移出

初始问析目录沿用现有快照登记的表。新出现的物理表和视图先出现在可用表发现结果中，管理员接入后进入模型可见目录。

| 管理接口 | 功能 |
| --- | --- |
| GET /catalog/tables/available | 列出当前数据源可读取的表、视图及接入状态 |
| POST /catalog/tables | 接入表并设置说明、字段含义和显式关系 |
| DELETE /catalog/tables/{name} | 将指定表移出问析目录 |
| POST /catalog/tables/refresh | 重新读取已接入表的字段、行数与外键 |

接入请求示例。

```json
{
  "name": "ExtraFacts",
  "description": "补充业务事实",
  "column_meanings": {"value": "实际值"},
  "relations": [
    {"from": "ExtraFacts.product_id", "to": "Products.product_id"}
  ],
  "expected_version": "从目录响应读取的 catalog_version"
}
```

expected_version 可省略。提供时校验当前目录版本。目录保存还会比较持久化 revision，避免并发写入覆盖其他变更。

接入时校验实际表、字段和关系端点，自动读取数据库声明的外键。关系参与问析需要两端表及字段均已接入。移出表后，当前目录过滤关联关系和引用该表的已发布指标，后续业务查询按当前目录重新检查绑定范围。

表接入和移出管理查询可见性。物理表继续由源数据库管理，历史 Artifact 保存当时的内容、SQL、来源和 catalog_version。历史结果的回读与派生计算继续依据其已有来源链进行。

重新接入时，省略说明、字段含义或关系字段会沿用已保存的设置。显式提供空字典或空列表可清空字段说明或关系，空字符串可清空表说明。元数据刷新会反映字段变化，将物理源中已缺失的表标记到 unavailable_tables。

## 持久化与版本

| 存储位置 | 内容 |
| --- | --- |
| PostgreSQL agent | 业务账本、会话事件和 table_catalog 表目录 |
| PostgreSQL agent_checkpoints | 图执行现场与暂停恢复 |
| PostgreSQL identity | 账号、认证会话、审计和反馈 |
| runtime/content | 历史和本次生成的实际产物 |
| config/harness.yaml | Profile、Bundle 和启动插件组合 |

source_id 标识只读数据源，catalog_version 根据数据源身份、当前可见表结构、说明、行数和有效关系生成。查询产物记录数据源与目录版本，snapshot_id 继续标识原有导入快照，semantic_version 继续标识业务语义定义。
